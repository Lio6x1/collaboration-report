# 在同一个空工程中，一步一步写完后端

这是现在的主学习路线：Windows、自己的同一个工程、自己创建后端文件和接口、复用现成前端。**不用克隆已有业务，不切换历史提交，不在中途换工程。** 教材直接采用当前整理后的文件，不必先写过细的旧文件再做两轮合并。

先体验[现成产品](../../operations/LOCAL-EXPERIENCE.md)，知道每个功能解决什么问题，再从第00阶段创建自己的工程。每课先说明“要实现什么功能、做完有什么效果、准备怎样实现、什么时候能验证”，再进入创建文件、写模型和接口、分步查询与业务、连接依赖及路由，最后运行测试并排错。所有功能课见[带写课程目录](lessons/README.md)。

每课使用三种相互配合的材料：

1. **功能讲义**：先给使用场景与完成效果，再解释实现思路、字段、参数、返回、执行顺序和正常/失败输入。
2. **分步操作页**：给每段准确写入位置和完整本步代码。讲义展示的同名声明就是操作页里的那一段，只写一次。
3. **章末完整答案**：写完后检查遗漏和最终装配，不再把整文件输入当作学习步骤。

每份分步操作页先解释“为什么创建这个文件”，列出执行路线和必须守住的边界，再给创建命令与逐步插入位置。声明旁说明字段、参数和返回值，复杂步骤结合实际条件、事务和异常路径讲解。说明表里的长表达式可能缩短展示，下面的本步代码始终完整；录入时以代码围栏为准，不能把说明中的省略号抄进程序。

第一次学习按功能讲义逐份创建文件，不需要先运行一大段批量建文件命令。部分课程章末保留可选快捷脚本，只为已经理解文件分工的人减少建目录操作；建出空文件不代表实现了功能。

完整产品有四个服务，同一个Go包中的用例可能互相引用。讲义标明前向依赖和第一次可build/test的位置；未写齐时不猜实现、不填假成功。独立纯规则可先验证，真实HTTP/WSS/存储及页面流程等四服务在06接齐后按模块运行。

不要从完整答案索引开始整份输入。先从功能讲义进入分步操作，保留已完成的代码；长函数还会按真实语句边界分段，结束前暂不gofmt。具体测试命令在各课和章末，文件摘要一致不能替代功能测试。前端不用重写组件，联调按06进行。

配套分为[手写源码机器清单](source-map.json)和[精确支持清单](support-index.md)。支持包含现成前端、测试、依赖锁定、生成DTO/RPC、契约原文及环境工具；SQL和手写后端不在支持包中。公开配置在configs，实例配置由脚本生成到自己的.runtime，禁止复制体验实例的数据和凭据。


新功能讲义、分步代码和独立学习工程的验证见[带写验证记录](09-teaching-verification.md)；先前的真实运行结果保留在[原工程记录](08-verification.md)。教师复原用来证明材料完整，不能替你完成亲写与验收；你自己的版本按[模块测试方法](../functional-testing.md)保留实际结果。本机全部功能正常后再学[服务器部署](../../operations/LINUX.md)，这里不操作远端服务器。
