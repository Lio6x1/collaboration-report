## 为什么创建这个文件

为应用用例提供同连接事务和三秒SQL期限。

从连接池分别执行BEGIN、业务SQL和COMMIT会落到不同连接，无法提供原子保存。

写之前先按这条执行路线理解各段的连接：

1. Transactions.run取得一个连接并START TRANSACTION
2. body(connection)的所有仓储调用复用此连接
3. COMMIT成功才返回body结果；finally尝试ROLLBACK并release

本文件需要守住的边界：

- COMMIT异常可能已落库，不能据异常推断回滚成功或发送SAVED
- finally中的ROLLBACK只是资源收尾，不能改变未知提交事实

## 第 2 步：Transactions

插入位置：第 1 步代码之后，紧接追加；完成稿约第 4 行。

本步声明：`export class Transactions `。

**这一段为什么这样写：** 把原子操作边界交给用例，以同连接提交日志和确认任务。

**跟着本段代码走一遍：**

- 等待 <code>this.pool.getConnection()</code> 完成才继续本异步函数；reject 会进入对应的错误处理路径。
- 等待 <code>query(connection, &#x27;START TRANSACTION&#x27;)</code> 完成才继续本异步函数；reject 会进入对应的错误处理路径。
- 等待 <code>body(connection)</code> 完成才继续本异步函数；reject 会进入对应的错误处理路径。
- 等待 <code>query(connection, &#x27;COMMIT&#x27;)</code> 完成才继续本异步函数；reject 会进入对应的错误处理路径。
- 此处通过 <code>return result;</code> 结束当前函数；注意返回的是哪一个阶段的结果。
- 等待 <code>query(connection, &#x27;ROLLBACK&#x27;)</code> 完成才继续本异步函数；reject 会进入对应的错误处理路径。

<!-- write-step: 2 bytes=220:672 -->
````javascript
export class Transactions {
  constructor(pool) {
    this.pool = pool;
  }

  async run(body) {
    const connection = await this.pool.getConnection();
    try {
      await query(connection, 'START TRANSACTION');
      const result = await body(connection);
      await query(connection, 'COMMIT');
      return result;
    } finally {
      try {
        await query(connection, 'ROLLBACK');
      } catch {}
      connection.release();
    }
  }
}
````
