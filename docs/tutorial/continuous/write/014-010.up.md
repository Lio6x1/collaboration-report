## 为什么创建这个文件

增加个人文档转让、资源空间计费分配与正文容量账。

资源原归属保持不变，转让改变的是明确文档的使用资格与计费空间；历史正文必须补真实容量。

写之前先按这条执行路线理解各段的连接：

1. personal_transfer固定双方、原文档控制修订及offer/accept原号。
2. resource_space_allocation按资源/空间记一次占用，document_resource_allocation固定转让后具体文档资格。
3. document_capacity回填非PURGED文档content_version字节，并增加quota_account.used_bytes。

本文件需要守住的边界：

- 补账即便超额也记录真实值，不提高limit；运行时允许查看/释放，拒绝新增。
