## 为什么创建这个文件

给个人文档的失效邀请和已处理申请保存管理归档事实。

用户删除管理记录时只隐藏列表，不能删除申请历史、原审批状态、原操作回执或已经获得的协作权限。

写之前先按这条执行路线理解各段的连接：

1. 先锁文档并重验管理权限，再锁原邀请或申请检查修订及状态。
2. 同一事务插入document_sharing_archive并推进原记录revision；管理查询以NOT EXISTS排除，申请人历史不排除。

本文件需要守住的边界：

- 不能归档OPEN邀请或PENDING申请；到期OPEN由业务投影为EXPIRED后允许归档。
- 复合主键区分两个表恰好相同的数字ID；归档表只授SELECT、INSERT，不给应用UPDATE/DELETE。

## 第 2 步：document_sharing_archive

插入位置：第 1 步代码之后，紧接追加；完成稿约第 3 行。

本步声明：`CREATE TABLE document_sharing_archive (`。

**先理解这一张表，再写下面的完整 SQL：**

| 列 | 数据库定义 | 保存什么、为什么需要 |
| --- | --- | --- |
| <code>record_kind</code> | <code>VARCHAR(16) CHARACTER SET ascii COLLATE ascii_bin NOT NULL</code> | 记录类别，只允许INVITATION或APPLICATION；与record_id共同标识归档对象。 |
| <code>record_id</code> | <code>BIGINT UNSIGNED NOT NULL</code> | 原邀请或申请的稳定编号；保留原表作为权威事实。 |
| <code>document_id</code> | <code>BIGINT UNSIGNED NOT NULL</code> | 所属文档的稳定编号，读写和权限校验必须同时绑定这篇文档。 |
| <code>actor_id</code> | <code>BIGINT UNSIGNED NOT NULL</code> | 发起或执行这次操作的账号编号，不能只用目标文档反推出操作者。 |
| <code>archived_at</code> | <code>DATETIME(6) NOT NULL DEFAULT CURRENT_TIMESTAMP(6)</code> | 管理者确认从列表移除的UTC时间；不替代原创建/审批时间。 |

键与约束：

- <code>PRIMARY KEY(record_kind,record_id)</code>：这一列组合唯一定位本表记录；同一组合不能插入第二行。组合键的所有列都参与身份判断。
- <code>INDEX sharing_archive_document(document_id,record_kind,record_id)</code>：按这里给出的列顺序建立访问路径，支撑对应范围查找和稳定翻页；普通索引不提供唯一性保证。
- <code>CONSTRAINT sharing_archive_kind CHECK(record_kind IN (&#x27;INVITATION&#x27;,&#x27;APPLICATION&#x27;))</code>：把这里列出的状态或数值范围交给数据库再次约束，业务代码校验之外再防止非法值落库。
- <code>CONSTRAINT sharing_archive_document_fk FOREIGN KEY(document_id) REFERENCES document(id) ON DELETE RESTRICT ON UPDATE RESTRICT</code>：把本表这些列绑定到被引用表的键，阻止无对应记录的悬空引用；删除和更新按这里声明的限制执行，不能跨服务数据库建立业务捷径。

NOT NULL 要求写入时提供值或使用声明的默认值；NULL 表示该事实尚不存在，不能随意以空字符串代替。时间按连接的 UTC 约定处理。

<!-- write-step: 2 bytes=123:746 -->
````sql
CREATE TABLE document_sharing_archive (
 record_kind VARCHAR(16) CHARACTER SET ascii COLLATE ascii_bin NOT NULL,
 record_id BIGINT UNSIGNED NOT NULL,
 document_id BIGINT UNSIGNED NOT NULL,
 actor_id BIGINT UNSIGNED NOT NULL,
 archived_at DATETIME(6) NOT NULL DEFAULT CURRENT_TIMESTAMP(6),
 PRIMARY KEY(record_kind,record_id),
 INDEX sharing_archive_document(document_id,record_kind,record_id),
 CONSTRAINT sharing_archive_kind CHECK(record_kind IN ('INVITATION','APPLICATION')),
 CONSTRAINT sharing_archive_document_fk FOREIGN KEY(document_id) REFERENCES document(id) ON DELETE RESTRICT ON UPDATE RESTRICT
) ENGINE=InnoDB;
````
