把Search消费者永久绑定到首次观察的Kafka物理日志身份。

同名topic可以被删除重建，旧offset在新日志中不再表示原消息。

本文件需要守住的边界：

- 不能仅比较topic名字；物理日志变化应拒绝接管旧checkpoint。

## 第 2 步：consumer_log_identity

插入位置：第 1 步代码之后，紧接追加；完成稿约第 3 行。

本步声明：`CREATE TABLE consumer_log_identity (`。

**这一段为什么这样写：** 永久绑定消费者首次使用的cluster/topic UUID，拒绝同名重建topic接管旧offset。

**先理解这一张表，再写下面的完整 SQL：**

| 列 | 数据库定义 | 保存什么、为什么需要 |
| --- | --- | --- |
| <code>consumer_name</code> | <code>VARCHAR(40) CHARACTER SET ascii COLLATE ascii_bin NOT NULL</code> | 消费者的稳定逻辑名称，不同消费者维护各自进度。 |
| <code>kafka_topic</code> | <code>VARCHAR(160) CHARACTER SET ascii COLLATE ascii_bin NOT NULL</code> | 消息所在 Kafka 主题；主题和分区共同确定偏移量的解释范围。 |
| <code>cluster_id</code> | <code>VARCHAR(160) CHARACTER SET ascii COLLATE ascii_bin NOT NULL</code> | Kafka集群标识，重建证明不能在不同集群间复用。 |
| <code>topic_id</code> | <code>BINARY(16) NOT NULL</code> | Kafka主题身份标识，主题删后重建同名也不应沿用旧证明。 |
| <code>revision</code> | <code>BIGINT UNSIGNED NOT NULL DEFAULT 1</code> | 本对象的修订计数，用于发现读取后发生的并发变化；不能用创建时间代替。 |
| <code>created_at</code> | <code>DATETIME(6) NOT NULL DEFAULT CURRENT_TIMESTAMP(6)</code> | 此记录创建的时间，保留原始创建事实；重试更新状态时不要重写成最新时间。 |

键与约束：

- <code>PRIMARY KEY (consumer_name)</code>：这一列组合唯一定位本表记录；同一组合不能插入第二行。组合键的所有列都参与身份判断。
- <code>CHECK (revision=1)</code>：把这里列出的状态或数值范围交给数据库再次约束，业务代码校验之外再防止非法值落库。

NOT NULL 要求写入时提供值或使用声明的默认值；NULL 表示该事实尚不存在，不能随意以空字符串代替。时间按连接的 UTC 约定处理。

<!-- write-step: 2 bytes=118:593 -->
````sql

CREATE TABLE consumer_log_identity (
  consumer_name VARCHAR(40) CHARACTER SET ascii COLLATE ascii_bin NOT NULL,
  kafka_topic VARCHAR(160) CHARACTER SET ascii COLLATE ascii_bin NOT NULL,
  cluster_id VARCHAR(160) CHARACTER SET ascii COLLATE ascii_bin NOT NULL,
  topic_id BINARY(16) NOT NULL,
  revision BIGINT UNSIGNED NOT NULL DEFAULT 1,
  created_at DATETIME(6) NOT NULL DEFAULT CURRENT_TIMESTAMP(6),
  PRIMARY KEY (consumer_name),
  CHECK (revision=1)
) ENGINE=InnoDB;
````
