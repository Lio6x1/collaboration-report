保存导出固定计划、临时制品校验信息以及独立临时磁盘预算。

导出是派生制品，不应重复计入用户资源额度；取消与过期仍需知道实际文件及预留量。

写之前先按这条执行路线理解各段的连接：

本文件需要守住的边界：

- 文件存在不代表导出成功，必须核对原任务、大小和摘要；012追加扩大硬上限，不能回改008。

## 第 2 步：export_control

插入位置：第 1 步代码之后，紧接追加；完成稿约第 4 行。

本步声明：`CREATE TABLE export_control (`。

**这一段为什么这样写：** 补充export_job的请求指纹、固定依赖、制品摘要和期限，未知转换可按原任务检验实际文件。

**先理解这一张表，再写下面的完整 SQL：**

| 列 | 数据库定义 | 保存什么、为什么需要 |
| --- | --- | --- |
| <code>job_id</code> | <code>BIGINT UNSIGNED NOT NULL</code> | 关联导出任务编号，制品与预算回执必须认回同一个任务。 |
| <code>fingerprint</code> | <code>BINARY(32) NOT NULL</code> | 操作输入的规范化指纹，用于核验重放是否仍是原请求。 |
| <code>snapshot</code> | <code>MEDIUMBLOB NOT NULL</code> | 导出创建时固定的权威输入快照，worker不能到执行时再拼接当前主线。 |
| <code>reserved_bytes</code> | <code>BIGINT UNSIGNED NOT NULL DEFAULT 0</code> | 已预留但尚未转为实际使用的字节额度，并发申请时先占位避免超额。 |
| <code>artifact_key</code> | <code>VARCHAR(64) CHARACTER SET ascii COLLATE ascii_bin NULL</code> | 导出临时制品的受控对象键，下载只认服务记录的键。 |
| <code>artifact_size</code> | <code>BIGINT UNSIGNED NOT NULL DEFAULT 0</code> | 转换完成后实际制品字节数，用于预算结算与下载核验。 |
| <code>artifact_checksum</code> | <code>BINARY(32) NULL</code> | 导出制品的内容校验摘要，下载前核验实际文件。 |
| <code>expires_at</code> | <code>DATETIME(6) NOT NULL</code> | 有效期终点；读取、兑换或恢复时仍须核验，不是只在创建时校验一次。 |

键与约束：

- <code>PRIMARY KEY(job_id)</code>：这一列组合唯一定位本表记录；同一组合不能插入第二行。组合键的所有列都参与身份判断。
- <code>INDEX export_control_expiry(expires_at,job_id)</code>：按这里给出的列顺序建立访问路径，支撑对应范围查找和稳定翻页；普通索引不提供唯一性保证。

NOT NULL 要求写入时提供值或使用声明的默认值；NULL 表示该事实尚不存在，不能随意以空字符串代替。时间按连接的 UTC 约定处理。

<!-- write-step: 2 bytes=231:701 -->
````sql

CREATE TABLE export_control (
  job_id BIGINT UNSIGNED NOT NULL,
  fingerprint BINARY(32) NOT NULL,
  snapshot MEDIUMBLOB NOT NULL,
  reserved_bytes BIGINT UNSIGNED NOT NULL DEFAULT 0,
  artifact_key VARCHAR(64) CHARACTER SET ascii COLLATE ascii_bin NULL,
  artifact_size BIGINT UNSIGNED NOT NULL DEFAULT 0,
  artifact_checksum BINARY(32) NULL,
  expires_at DATETIME(6) NOT NULL,
  PRIMARY KEY(job_id),
  INDEX export_control_expiry(expires_at,job_id)
) ENGINE=InnoDB;
````

## 第 3 步：export_budget

插入位置：第 2 步代码之后，紧接追加；完成稿约第 17 行。

本步声明：`CREATE TABLE export_budget (`。

**这一段为什么这样写：** 单行记录导出临时磁盘reserved与used，所有worker竞争同一锁，不与用户quota混算。

**先理解这一张表，再写下面的完整 SQL：**

| 列 | 数据库定义 | 保存什么、为什么需要 |
| --- | --- | --- |
| <code>id</code> | <code>INT UNSIGNED NOT NULL</code> | 本表记录的稳定标识；具体由自增分配还是由调用者传入，以本列定义为准。 |
| <code>reserved_bytes</code> | <code>BIGINT UNSIGNED NOT NULL DEFAULT 0</code> | 已预留但尚未转为实际使用的字节额度，并发申请时先占位避免超额。 |
| <code>used_bytes</code> | <code>BIGINT UNSIGNED NOT NULL DEFAULT 0</code> | 已经实际占用的字节额度；释放必须认回原制品，不能重复扣减。 |

键与约束：

- <code>PRIMARY KEY(id)</code>：这一列组合唯一定位本表记录；同一组合不能插入第二行。组合键的所有列都参与身份判断。
- <code>CHECK (id=1)</code>：把这里列出的状态或数值范围交给数据库再次约束，业务代码校验之外再防止非法值落库。
- <code>CHECK (reserved_bytes&lt;=268435456 AND used_bytes&lt;=268435456)</code>：把这里列出的状态或数值范围交给数据库再次约束，业务代码校验之外再防止非法值落库。

NOT NULL 要求写入时提供值或使用声明的默认值；NULL 表示该事实尚不存在，不能随意以空字符串代替。时间按连接的 UTC 约定处理。

<!-- write-step: 3 bytes=701:975 -->
````sql

CREATE TABLE export_budget (
  id INT UNSIGNED NOT NULL,
  reserved_bytes BIGINT UNSIGNED NOT NULL DEFAULT 0,
  used_bytes BIGINT UNSIGNED NOT NULL DEFAULT 0,
  PRIMARY KEY(id),
  CHECK (id=1),
  CHECK (reserved_bytes<=268435456 AND used_bytes<=268435456)
) ENGINE=InnoDB;
````
