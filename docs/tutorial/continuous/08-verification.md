## 遇到的问题及处理

1. npm首次使用本机共享缓存被拒绝，改为学习工程内缓存，锁定ci成功；未修改全局npm。
2. Docker默认地址池耗尽。只读核现有Docker网段与主机路由后，为新owner创建不重叠的10.231.80.0/24默认网络，标签保持Compose项目和owner；未清理其他网络。首次迁移安装到012，四服务在20623 READY。
3. 协作最初通配符把真实readiness放进缺配置阶段，95项独立检查通过而该文件失败；课程纠正阶段归属，启动后原readiness5项实际通过，不以跳过充当成功。
4. 搜索可见性旧测试假定回收文档event_seq仍为0。当前DELETE事务确实推进隐藏事件；测试改为原水位+1，同时核publication_epoch及原Canal/Kafka/ES消费，4项可见性检查通过。
5. 资源旧测试假定空间used_bytes只含上传文件，漏了空文档规范正文容量。改为真实初始余额加精确资源增量，保留重复结算、在途互斥、过期退款和正文费用断言，真实上传检查通过。
6. 导出及生命周期测试仍找旧ActionStatus按钮文字，统一到当前“确认操作结果”，保留响应丢失后原号重试检查。并发池测试的专用账号文件从默认必需改为显式可选，默认走隔离开发SMTP身份；不复用体验产品凭据。真实三格式和回收恢复均已通过。另四份生命周期脚本只同步同一按钮定位，未把其整份流程称为本轮已执行。
7. 并发池原测试在读到RUNNING后调用慢Windows归属核验，转换可能已经完成，旧观察不能证明被中断。修正为先锁定三个测试作业的完成事务边界，不写状态；确认原Doc实际退出后解除行锁，再降为默认单worker恢复。实际两原作业代次2→3、排队作业1→2，全为SUCCEEDED、预留归零；制品校验和、各自正文、重放与私有下载拒绝全部通过。不是放宽代次断言或手改任务终态。
8. 回收浏览器测试仍找旧知识库下拉框及页底折叠入口。已按当前“组织空间→组织名称→侧栏回收站”更新，不再要求先选库；保留真实恢复、响应丢失后同号确认、刷新与空列表断言，完整流程通过。
