# 教师带写课程目录

先完成[00空工程准备](../00-start.md)，以后始终在同一学习目录。每课先说明要实现什么功能、完成后能看到什么、准备怎样实现和何时验证；理解这些之后才进入文件分工、模型/接口、业务与SQL、接线和测试。讲到哪个文件就按对应分步页创建并录入，章末批量建文件脚本只是可选快捷方式。功能讲义与操作页中的同名声明只写一次，完整答案用于章末核对。

“文件语法通过”“包或服务构建通过”“纯规则通过”“真实接口/存储通过”分别成立，不能互相替代。各课标明前向依赖和可执行关口，不要求写到一半时猜未来实现。

## 01 公共底座、正文契约和SQL

这一阶段为后续保存正文、注册账号和跨服务操作建立基础：同一正文得到相同字节，业务数据有持久归属，服务能安全启动，断网后的操作有恢复依据。这里还没有完整用户页面。

先用具体正文样例理解校验，再设计数据表、启动与错误出口、原操作协议和重建文件。F01可独立测试；F03引用F04的同包声明，写齐后运行平台规则；F05两个子包独立检查。SQL到06自己的实例才安装。

## 02 账号、验证码、组织与会话

这一阶段实现用户进入系统后的账号与团队功能：邮箱注册、登录、修改密码和邮箱、创建组织、邀请或审批成员、接收通知，以及安全退出与注销。接通后，合法用户能完成这些操作，无效凭据或不足权限会被拒绝，断网重试可以恢复原结果。

先从“输入邮箱和密码怎样登录”理解一条完整链路，再扩展验证码、身份与组织管理，最后补通知、关闭和恢复。A08把业务接入HTTP、RPC和后台任务；账号包存在前向引用，整体构建到A08执行，真实邮件与页面流程在06验证。

## 03 文档、权限与完整工作流

先明确谁能操作哪份文档，再依次完成工作区、主线与支线、章节、审核、发布、图片、评论和导出，最后处理撤权、回收转移与搜索接线。D14是文档整包构建关口；转换器也依赖尚待写齐的业务声明，真实功能在06验证。

## 04 Node协作与可靠保存

这一阶段让多人真正共同编辑：输入的内容得到可靠保存，重连后可恢复；送审和合并使用固定内容，拆章时保护在线编辑者的输入，撤权后旧连接停止工作。正文与权限的权威结果仍由文档服务配合确认。

先理解一次正文更新如何检查和恢复，再连接准入、落库后的保存确认与保存证明；随后实现撤权、固定工作流、在线结构协调和清理，C07完成网络与进程装配。语法检查不等于多人保存成功，全部依赖齐备后跑规则，真实WSS与数据库在06验证。

## 05 正式版搜索与索引恢复

这一阶段实现正式版文档搜索：发布后进入索引，用户按关键词查询和翻页，撤下或失去权限后不再暴露正文。服务重启能继续消费变更，索引需要重建时可追赶期间变化并安全切换。

先理解发布事件如何变成可搜索内容，再保存消费进度、实现候选分页，最后准备快照、回填、追赶和切换。搜索索引是可重建副本，当前阅读资格由文档服务复核；三个存储系统不是一个事务，未知结果必须恢复原事件。S05完成全包接线，06验证真实搜索与重建。
