# 校招面试自测

先不看答案，用你自己的话回答，再定位实现与实际证据。不会的部分回到对应章节补练习。每个回答按“用户场景→风险→实现→证据→边界”组织；不要背一串组件名。

## 九个必须能讲清的问题

| 问题 | 回答必须包含的事实 | 回到哪里 |
| --- | --- | --- |
| 为什么Yjs同步成功不等于保存成功？ | 候选隔离、校验/资源保护、同事务持久日志、提交后广播与SAVED，FLUSH原依赖 | C01～C02 |
| 同时改密码与登录怎样处理？ | bcrypt在锁外减少持锁，锁用户后重检hash/state/credential_epoch，再建session | A01～A02 |
| 权限怎么避免前端伪造？ | 身份来自会话及内部证明，Doc用自己库的当前权限事实，mTLS还需方法能力检查 | F04、A02、D01 |
| 超时后为什么不能重建一个operation？ | 提交可能已经发生，原号+固定摘要+持久任务/回执恢复；成功与UNKNOWN分开 | D05～D06、D11～D12 |
| 固定送审后继续编辑会影响审核吗？ | round/content_version/manifest绑定固定输入，后续草稿是另一份事实 | D05 |
| 为什么撤权要等待输出关闭？ | 先关闭准入，发出取消，再证明HTTP/WSS结束，登记原ACK；网络栈已交付字节不能收回 | C03、D11 |
| Canal/Kafka/ES怎样保持可恢复？ | Doc事务outbox、真实消费、投影顺序/水位、SQL回执与Kafka offset不同步骤，原消息重放 | S01～S05 |
| 图片什么时候才能删？ | READY引用/保护、各上下文固定资源、最后引用释放、实际字节删除与退款；不能只看对象年龄 | D08、D12～D13 |
| 导出与恢复怎样证明真实？ | 固定版本/资源、转换作业原号、权限输出；冷备份停止写入，校验字节和恢复原任务/水位 | D10、备份恢复参考 |

## 追问练习

1. 手画一次保存调用链，圈出事务提交和两种ACK的位置。把资源保护改到提交之后，会产生什么风险？
2. 手画一次审核合并，从固定输入到主线READY。RPC返回丢失时，哪些事实让同号继续？
3. 找一条真实搜索消息，解释ES已经成功、SQL回执尚未落定时为何可以重放；同序号不同摘要如何处理？
4. 找一处repository函数，证明它使用logic传入的同一事务。为什么不能让每个DAO函数自己提交？
5. 解释本机owner归属检查：仅PID、仅进程名、仅容器名字分别有什么问题？
6. 只在学习目录将一个关键约束改弱，让对应已有测试失败，再恢复。保留命令与失败断言，说明你理解了哪个保证。

## 项目介绍说法

可以先讲：“这是一个团队协作报告系统，包含真实多人编辑、固定版本审核发布和搜索。我重点学习了可靠保存、权限撤销以及跨服务原号恢复。”然后选择你亲自重建、改过并验证的两条链路深入展开。

不要把辅助开发工具的工作写成自己的独立原创。可以如实说明使用了AI辅助搭建与检查，并展示你完成的章节练习、设计解释、故障定位和修改。简历描述需要与你能现场讲清的部分一致。

不使用没有数据支持的吞吐量、用户量、线上SLA或“零丢失”承诺。若引用自己实际运行的协作或正文规模演示，带出机器、工作负载、时间窗口、指标，并区分[当前验证范围](../delivery/CURRENT-REVIEW.md)；本机测试不代表2GiB服务器容量。Linux整站部署、公网域名和实际SMTP应按完成状态描述。
