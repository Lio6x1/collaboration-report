# 一次可复现的项目演示

当前界面：工作台左侧为知识库、全部文档、协作申请、回收站，右侧显示当前内容；新建/加入用短弹窗，知识库设置分基本信息、成员、权限；知识库从封面卡片进入；阅读页的协作、审核、评论分别成模块，编辑在当前标签切换工作区；评论回复和原文默认折叠，版本显示发布时间。学习版本须完成[当前全量课程](continuous/README.md)。

演示需使用已经完成编写与验收的完整版本。现成体验实例按[本机体验说明](../operations/LOCAL-EXPERIENCE.md)进入；自己写完的当前学习版按[学习目录专用启动步骤](continuous/06-integration.md)初始化。以实际启动日志输出的HTTPS入口为准，不硬编码历史端口或把体验产品路径套到学习目录。本机中间件由Docker Compose启动；邮件按自己实例的真实SMTP或开发收件模式查收。

## 准备

在同一浏览器打开两个标签，分别主动登录A和B，核对各自右上角昵称，再开始多人演示。当前版本通过标签会话上下文选择不同HttpOnly Cookie；复制标签可能继承同一上下文，主动登录会轮换槽位。也可继续使用两个独立浏览器配置或隔离上下文；匿名窗口用于公开阅读。具体规则见[登录态与CSRF](frontend-integration.md#登录态与csrf)。只使用专门的演示账号、知识库和文档，生命周期演示会真实删除样本。

A注册并建立组织和知识库，B注册、申请加入，由A审批。按页面可选范围授予B需要的编辑和审核能力；编辑可以是UNIT范围，不能为方便演示把不存在的DOCUMENT EDIT输入当合法请求。用包含时间的唯一标题与正文标记，防止搜索命中旧文档。可提前准备一张小PNG。

开发邮件读取命令在项目根运行：

```powershell
./scripts/show-mail.ps1 -Email 'demo-a@example.test' -Limit 1
```

验证码、Cookie、口令与OSS密钥不录入公开录像或截图。公网真实SMTP尚未配置时，这个命令只适用于本机开发邮件。

## 主要演示顺序

| 步骤 | 页面操作 | 观察与解释 |
| --- | --- | --- |
| 1. 建文档 | A创建专用演示文档并进入编辑，B打开被授权的同一文档 | 两位真实账号，各自身份来源与权限 |
| 2. 多人保存 | A、B分别写不同段落；A插入PNG，等待已保存状态，再刷新 | 两人的文字和图片都存在；同步可见与持久保存是两个步骤 |
| 3. 固定审核 | 准备个人支线，先拉主线再编辑；送审，审核人打开固定正文并合并 | 新改动不会替换已送审版本，合并完成后主线实际包含标记 |
| 4. 批注提醒 | 正文展开评论侧栏，对选区发评论并从合法候选中@另一人；在评论区展开回复、在对方通知页打开 | 正文标记与原引用定位，原文按需展开；历史引用不伪装当前位置，收件范围来自当前资格 |
| 5. 发布检索 | 合法管理者选择公开策略、点击“发布可靠主线”；匿名打开当前正式版，再到“正式版搜索”搜唯一标记 | 正式版固定；搜索异步经过消息消费，未出现时观察原处理状态，不直接改ES |
| 6. 导出 | 从页头“导出文档”选择PDF，点击“创建导出”，观察原作业至完成后下载 | 后台有限worker转换，无cmd弹窗；文件对应固定输入，等待中续看原号，打开PDF核正文、图片与长代码分页 |
| 7. 回收恢复 | 回收专用文档，匿名入口不可读；从回收站恢复 | 恢复后的文档为私有、未发布，正文仍存在 |
| 8. 完全清理 | 再回收，仅对演示样本确认永久删除，观察原清理作业结束 | 删除是业务与引用清理流程，不只是SQL删一行 |

如果现场时间有限，优先展示2、3、5、6，生命周期和故障恢复用已有实际日志解释。撤权演示可另用专用文档撤掉B的授权，观察旧编辑连接停止；不要在同一主要演示中破坏后续需要的权限。

## 验收怎样留证据

手动演示记录角色、文档ID、原操作号、固定版本、实际状态和截图。一次截图仅证明这个页面，不证明全部权限或恢复。真实整站脚本在[第13章完整装配与整站](continuous/06-integration.md)，执行自己的学习环境；历史整站、OSS与恢复证据见[第八批](../delivery/CURRENT-REVIEW.md)，不为了演示重复全部故障矩阵。

先体验现成产品，再按教程完成自己的后端。自己的版本本机全部功能正常后才部署Ubuntu服务器；服务器部署后按相同步骤复核主要功能。服务器用于少量人员体验，不把本机并发测试结果归到该服务器。

## 当前导航体验顺序

在工作台先点“个人空间”，核中间位置和个人知识库一致；再点“组织空间”，从“组织”下拉框选择组织名称，核只显示这个组织的目录。若当前页还没加载到组织，先点“更多组织空间”；全部加载后仍为空，应显示没有可访问组织的说明。选定组织后刷新，仍应恢复同一有权组织。点库封面进入文档目录，通过“知识库设置”查看各管理分区，再返回；新建弹窗明确显示“创建到”，可先填写再关闭，重开核输入保留，本步骤无需提交。切到回收站或个人空间下的协作申请，核页面只展示当前任务；浏览器后退应恢复合法目录。组织页的“我的组织申请”进入独立进度，创建/加入通过弹窗办理。

从顶部“更多 → 账号设置”查看账号信息、修改密码、修改邮箱依次纵排；桌面表单限宽居中，手机无横向溢出。布局演示无需修改真实密码或邮箱。顶部“通知”只演示现有“打开相关内容”和“返回通知”；“标记已读”单独操作。通知精准定位、刷新目标恢复和当前任务处理入口等增强已按用户要求暂缓，不作为这次演示的已完成功能，见[当前通知说明](continuous/reference/page-acceptance.md)。

编辑时分别打开表格、公式、Markdown和图片浮层，核互斥、外点与Escape。插入表格/公式后浮层自动收起。上传中的图片切换浮层继续完成，不能因视觉隐藏就另建上传。审核的“处理合并冲突”进入独立工作区，原基线/原送审/原主线分开核对；返回列表再进入保留候选，“关闭工作台”才移除候选。保存规则与原轮次、撤回状态和权限一致，不能用演示输入替换真实冲突绑定。
