# Windows资源上传运行说明

资源由Doc服务保存，浏览器使用同源HTTPS、登录会话和CSRF。创建上传返回的URL只是入口，不能代替上传者及当前文档编辑/管理资格。

## 配置与容量

开发默认资源目录为仓库`.runtime/resources/document`，使用支持硬链接与文件锁的NTFS目录。不要手工删除运行中的`.lock-*`文件。锁文件永久保留，以免删除后重建产生两把不同的锁。

Doc配置可以显式提供完整的`resources`对象：

```json
{
  "resources": {
    "root": "D:/collaboration-data/resources",
    "spaceBytes": 1073741824,
    "uploadBytes": 33554432,
    "temporaryBytes": 268435456,
    "uploadTTLSeconds": 3600
  }
}
```

不设置该对象时使用上述额度和仓库默认目录。单文件上限不能超过32MiB，有效期可配置为60～86400秒。每空间容量与上传暂存容量分别记账；暂存预算从创建上传起占用，直到完成或实际清理成功才释放。010起空间已用量包含不可变业务 canonical 正文，以及跨空间转让时固定计量的 Node 存储。011增加实时正文预留：Node提交前按每个房间/epoch的 canonical 正文高水位保护增长差额，同房间协作者不重复扣整篇。真实持久证明到达后原预留才结算为已用；未知占用不会因TTL自动释放。

满额时仍可读取固定主线、导出和清理。只读副本单独登记运行容量，刷新页面时不会再次扣减用户额度。缩小正文可以保存，资源回收须等协作状态与文档历史实际清理完成。规划磁盘容量时，另行计入 Yjs 日志、阅读副本、正式文件、索引、备份和暂存预算。

`spaceBytes`和`temporaryBytes`仅初始化首次创建的数据库预算，修改配置不会覆盖已有账户额度。需要调整已有额度时应执行受控迁移，不能直接重算或清零在途预留。

## 上传顺序与恢复

1. `GET /v1/spaces/{spaceId}/quota`读取实际配额版本。
2. `POST /v1/documents/{documentId}/resources`携带原操作号、配额版本、字节数、媒体类型和SHA256摘要。
3. 对返回URL执行二进制PUT。服务端验证完整长度和摘要；成功仍为UPLOADING。
4. `POST /v1/resources/{resourceId}/complete`使用独立操作号，确认后资源才是READY，并将预留容量转为已用容量。

创建或完成响应丢失时重试原操作号和原输入。占用冲突返回`RESOURCE_UPLOAD_BUSY`时等待当前请求结束再重试，不要生成另一份上传逃避原预留。字节或摘要不匹配会拒绝，不能把错误响应当成已完成。

过期的未完成上传由Doc后台恢复：先关闭为DELETING，删除精确文件和半文件，再提交DELETED及预算释放。实际写入还在进行时，清理不能抢走文件锁。进程退出后操作系统释放锁，恢复继续原持久状态；不要以TTL到期或请求取消作为已经删除的证据。

## 开发启动观察

在仓库目录执行：

```powershell
node --no-maglev scripts/start.mjs
```

若返回`COLLABORATION_BOOTSTRAP_TIMEOUT`或`SERVICE_READINESS_TIMEOUT`且`.runtime/startup.json`为`OBSERVATION_TIMEOUT`，表示尚未观测到就绪。稍后执行同一命令会核验并续接原进程，不要先执行stop反复重建。必须收到真实READY结果后再使用服务。已有实例退出或归属不匹配时会明确拒绝续接，不宣称就绪。

修改Doc后需要更新运行程序时，使用监督器整组`stop`再`start`，保留数据库。不要单独重启Doc并保留旧Edge：当前输出恢复必须证明旧输出进程退出，旧Edge存活时会拒绝启动。

当前实现使用本地存储；OSS适配及其共享互斥仍属后续交付。

READY资源的原上传期限结束后，额外保留一小时用于插入正文。此时仍无草稿、版本、保留任务引用或未释放保护的对象，才会进入回收；单独上传成功而长期未插入的图片会被清理，需要重新上传。此规则不延长原上传期限，也不修改原上传回执。

回收持文件排他锁，在资源行锁下复核全部引用，先提交DELETING阻止新增引用，再执行物理删除；最后将DELETED和used容量扣减一起提交。COMMITTED上传收据保留，便于审计且不会再次释放暂存或reserved。文件或提交结果未知时保留持久状态，下一次继续原对象。历史版本/草稿保留策略仍须证明引用已不需要后才能移除引用，GC不会凭时间推断这些引用失效。

## 正文引用与下载

正文只保存`resourceId`。图片上传成为READY后，通过编辑器插入并等待服务端保存；上传成功本身不授予正文下载资格。

`GET /v1/resources/{resourceId}/content`需要`document_id`、`context_kind`、`context_id`三个参数：

| context_kind | context_id | 下载约束 |
| --- | --- | --- |
| MAIN | 阅读清单manifest_id | 当前锁定主线清单，或本人会话尚有效的阅读快照；资源属于清单固定版本 |
| BRANCH | 当前branch_id | 当前支线编辑资格；资源属于该支线基线或当前房间代次已保存引用 |
| REVIEW | review_round_id | 当前审核读取资格；资源属于该轮次固定正文、基线，或尚有效原冲突的已核验固定输入 |
| PUBLIC | 当前release_id | 当前正式版受众资格；资源属于该正式清单，撤下或切换后原地址失效 |

文件地址不是永久凭证。私有下载需要登录；匿名只允许具有公开资格的PUBLIC上下文。PNG/JPEG/GIF/WebP使用图片响应，其他媒体类型按附件返回。响应禁止缓存，完整文件校验不占用数据库事务，下载共享锁与删除排他锁互斥。输出沿用Doc和Edge撤权租约。

原冲突输入图片沿用其REVIEW轮次，但必须有同轮次尚有效原冲突收据及真实固定版本证明；当前主线不能替代历史输入。生命周期引用释放、Node真实CLEANED和实际进程退出清理恢复已通过第六/七批主线。

个人转让不修改图片原物理空间。只有实际已接受文档、目标空间分配和当前上下文资格同时成立，才能读取跨空间图片；其它源文档仍引用时保留原空间计费。同一空间共享图片只记一次。清理迁入文档后，该空间最后消费者消失而其它空间仍使用时，只退款已空的空间分配，保留物理文件与COMMITTED上传记录；全部消费者消失仍等待实际GC DELETED才退款。正文清理按真实剩余固定公开版本结算，不能按删除请求到达就退款。
