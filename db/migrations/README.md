# 数据库迁移

`013`增加`document_sharing_archive`：管理者可以移除失效邀请与已处理申请的管理记录，原状态、审批历史、操作回执和已有授权保留，申请人自己的历史不受影响。应用仅有SELECT、INSERT，归档和原记录revision推进在同一事务。已有实例连续追加013，不能重建表或修改旧迁移。

`012`将导出预算的数据库硬上限从256MiB扩大到2GiB，支持最多8个worker。应用仍按配置的实际并发核算额度，默认1保持256MiB；不修改008原字节、既有任务或预算余额。安装器精确核验旧约束、已启用的新约束及连续四库回执，未登记的新约束不能当作已成功升级；服务配置同步版本12摘要后才能就绪。

当前连续版本到`013`。`010`补齐正文历史及转让/资源分配账；`011`增加房间正文高水位、原号预留与只读阅读容量表。新的原 UPDATE 在Node提交前取得预留，真实COMMITTED证明后结算；生命周期只有真实CLEANED才能释放未知预留和已清正文。旧READ_VIEW仅在可证明没有业务清单引用时纠正费用，不改正文、上限或旧迁移摘要。服务最小表权限随`service-grants.sql`更新，不能仅完成DDL而遗漏应用权限。下文001/002说明保留其初始安装语义，实际安装器按当前全部父摘要连续追加。

`001.up.sql`和`schema-manifest.json`保存最初的100张表及144个外键；已经安装的文件原字节与SHA不能改写。`002.up.sql`追加11个覆盖索引，`002-manifest.json`绑定001摘要、002原字节摘要及精确索引列定义。

在项目根目录的Windows PowerShell运行：

```powershell
./scripts/npm.ps1 run bootstrap
```

安装器持有同一个命名锁，先核对四库相同的已安装版本前缀。已有完整001只追加002，完整002重复调用返回`ALREADY_INSTALLED`；新库依次安装001和002。索引定义核验包含列顺序、非唯一BTREE、无前缀、可见及升序。全部DDL完成才登记版本2，不通过同名存在就猜测已经安装。

MySQL DDL不能整体回滚。缺少某库、不同版本、错误摘要、未登记的新索引或错误索引定义都应拒绝；失败后保留现场，先检查原事实，不能删除原表、重新播放001或篡改旧摘要。应用账号没有DDL或迁移记录写权限，只有环境安装器使用单独的管理账号。

服务配置的`expectedSQLSHA`继续核对001；`expectedAdditionalMigrations`由已校验的本地发布文件生成，并逐版本与数据库记录比较。旧配置不能忽略数据库里的版本2，缺失、重复、未知版本或错误摘要都返回不可用。

`task_pending`用于基础恢复事实检查；`gate_recovery`与`auth_recovery`用于关闭水位事实；文档`task_kind_due`用于窄候选检索。候选ID查询不加范围锁，最后仍按原主键当前读锁、原代次和同一事务payload领取；索引不是授权依据，不能用它绕过来源锁或未知结果处理。

512MiB缓冲池、2GiB总内存上限、原SQL/HTTP/RPC及就绪期限保持。是否消除容量前置后的失败必须以实际原恢复、篡改及完整产品验收证明，单独EXPLAIN不算完成。

`003`～`005`沿连续父摘要追加搜索分页、重建快照和消费日志身份；`006`追加Node固定正文副本的`cleanup_document`虚拟派生列与`task_document(cleanup_document,kind,id)`索引。派生值由原payload的四种既有文档绑定路径计算，与正文登记在同一MySQL事务维护。清理只按该文档与已知kind查询；索引仅用于定位，执行前仍核验原Doc计划、原来源/ACK、未知操作与实际房间输出。

`006-manifest.json`同时声明派生列的类型、排序规则和生成表达式。安装器核对实际表达式；MySQL返回的反引号、字符集前缀和转义格式可以规范化，JSON路径大小写及字面量中的空格必须原样比较。错误表达式不能因索引同名或列名相同而认可。已有库只追加缺少的连续版本，保留所有历史版本的原字节与回执。
